================================================================================
                          ROOT CAUSE ANALYSIS
================================================================================

CRITICAL FINDINGS:

1. NO PASSWORD FIELD IN DATABASE
   - User.js schema had no password field
   - No password storage capability in MongoDB
   - All password handling delegated to Firebase (production only)
   - Dev mode had no password verification

2. DEV ENDPOINTS IGNORED PASSWORDS
   - registerDev() accepted but discarded password parameter
   - loginDev() didn't verify passwords
   - Any email/password combination worked
   - No password verification mechanism

3. MOCK TOKENS HAD NO EXPIRATION
   - Mock tokens were simple strings like "mock-token-{userId}"
   - No signature, no expiration, no validation
   - Indefinite access with no revocation

4. NO ACCOUNT LOCKOUT PROTECTION
   - No brute-force attack protection
   - Unlimited login attempts allowed
   - No failed attempt tracking

5. WEAK PASSWORD REQUIREMENTS
   - Only 6 character minimum
   - No complexity rules (uppercase, lowercase, digit, special char)

6. TOKEN KEY MISMATCH
   - AuthContext stores token as "authToken"
   - api.js retrieves token as "dc_token"
   - Token stored but never retrieved for API calls
